# AR 오버레이 시안 구현

`hud_theme.py` 는 전달주신 디자인 문서의 하이파이 시안 `2a` / `2b` 를 OpenCV 로
구현한 것입니다. 라즈베리파이에서 그대로 돌아갑니다.

```bash
python3 hud_ui.py preview --theme --windowed   # 시안 미리보기
python3 hud_ui.py receive --theme              # 실제 수신 + 시안 표시
python3 hud_ui.py bench   --theme              # 이 장치에서 속도 측정
python3 hud_ui.py sample  --theme --out png    # 상황별 PNG 저장
```

`--theme` 없이 실행하면 이전의 단순 선 표시가 나옵니다. 설정에
`"ui": { "style": "ar_overlay" }` 를 넣으면 항상 시안으로 뜹니다.

## 먼저 설치

기본 서체가 없으면 대체 서체로 떨어집니다. 파이에서:

```bash
sudo apt install -y fonts-ibm-plex fonts-nanum
```

`fonts-ibm-plex` 가 없으면 DejaVu Sans Mono 로, 한글은 나눔고딕이나 Noto CJK 로
대체됩니다. 대체되어도 동작에는 문제가 없고 글자 모양만 달라집니다.

## OpenCV 로 옮기면서 다르게 한 것

디자인 문서의 값은 그대로 따랐지만, OpenCV 와 반사식 HUD 의 제약 때문에
구현 방식이 달라진 부분이 있습니다.

### 그라디언트

OpenCV 에는 그라디언트 stroke 나 fill 이 없습니다. 그래서 마스크를 먼저 그리고
세로 방향 알파 램프를 곱하는 방식으로 만들었습니다. 문서의 정지점을 그대로 씁니다.

| 대상 | 정지점 |
|---|---|
| 채움 | .26 → .10 (0.55) → 0 |
| 경계선 | 1 → .72 (0.62) → 0 |
| 감광 경계선 | .34 → .12 (0.7) → 0 |
| 경고 채움 | .30 → .10 (0.55) → 0 |

### 페이드와 틱의 기준이 바뀌었습니다

문서는 소실선을 `y=172`, 리본 하단을 `y=540` 으로 두고 거리 틱을
`503 / 428 / 360 / 296 / 240 / 198` 에 고정했습니다. 이건 리본이 화면 바닥까지
내려온다는 전제입니다.

**실제 HUD 는 도로의 좁은 띠만 덮습니다.** 7인치 패널 기준으로 앞 5~40m 정도이고,
그보다 가까운 노면은 패널 좌우로 빠져나갑니다. 고정 y 를 그대로 쓰면 틱이 리본
바깥에 그려져 하나도 안 보이고, 페이드도 리본 전체가 거의 투명해집니다.

그래서 문서의 y 값을 **리본 안의 상대 위치로 환산해서** 씁니다.

```
503 → 0.100    428 → 0.304    360 → 0.489
296 → 0.663    240 → 0.815    198 → 0.929
```

0 이 리본 하단, 1 이 소실선 쪽 끝입니다. 이렇게 하면 HUD 가 어느 구간을 덮든
비율이 유지됩니다. 문서 Open questions 3번(거리 매핑 재산출)에 대한 답이기도 합니다.

또한 패널 좌우로 빠져나간 근거리 구간은 리본에서 제외합니다. 그대로 두면 채움이
화면 아래쪽을 통째로 덮어 시야를 가립니다.

### 크롬이 리본을 피합니다

같은 이유로 정합 칩(`y=86`)이 리본과 겹칩니다. 실제 HUD 는 소실점이 화면 위쪽에
오기 때문입니다. 칩과 상태 스트립이 리본 밖으로 자동으로 비켜나도록 했습니다.
`theme.chrome_avoids_ribbon` 을 `false` 로 하면 문서 좌표를 그대로 씁니다.

### 알파 합성 대신 가산 합성

HUD 는 발광 디스플레이라 겹치는 빛이 밝아집니다. 그래서 `over` 합성이 아니라
가산으로 쌓습니다. 광학계 동작과도 맞고, 측정해보니 6배 빠릅니다.

### 패널 배경은 보이지 않습니다

문서의 `hud/panel` `rgba(5,7,10,.55)` 는 거의 검정입니다. 반사식 HUD 에서
검정은 곧 투명이라 유리에 아무것도 안 맺힙니다. 그래서 상태 스트립과 배지는
**테두리와 글자만** 보입니다. 시안 이미지와 다르게 보이는 게 아니라, 원래 그렇게
동작하는 것이고 문서에도 `hud/bg` 항목에 같은 취지가 적혀 있습니다.

### 글로우

`feGaussianBlur stdDeviation 3.2` 를 축소 → 블러 → 확대 → 가산으로 구현했습니다.
`theme.glow_scale` 이 축소 배수입니다. 값이 클수록 빠르고 뭉개집니다.

실차에서는 광학계 자체의 블룸이 더해지므로 `theme.glow_gain` 을 낮추는 편이
안전합니다. 문서에도 같은 권고가 있습니다.

## 상태

| 상태 | 진입 조건 | 표시 |
|---|---|---|
| `BOOT` | 기동 후 1.2초 | 경계선 드로잉 + 틱 상승 스윕 |
| `LOCKED` | 기본 | 시안 `2a` |
| `LOW_CONFIDENCE` | `confidence < 0.45` | 리본 60% 감광, 경계선 점선, 칩 앰버, 게이지 1단 |
| `DEPARTURE` | `warning` 이 `departure_*` | 시안 `2b`, 이탈 측만 강조 |

경고 점멸은 820ms 주기입니다. 경계선은 `steps(1,end)` 하드 온오프
(불투명도 1 ↔ .18), 채움은 ease-in-out 펄스(.10 ↔ .30)로 문서와 같습니다.
경고 중에는 부팅 애니메이션을 생략합니다.

## 추론 코드에서 보내는 값

`HudUiSender.send` 에 항목이 늘었습니다.

```python
from hud_ui import HudUiSender

hud = HudUiSender("192.168.50.20", 5005)

hud.send(
    lane_polylines_px,
    frame_width=frame.shape[1],
    frame_height=frame.shape[0],
    warning="departure_left",     # none / departure_left / departure_right
                                  # change_left / change_right
    confidence=0.82,              # 0~1, 게이지와 LOW_CONFIDENCE 판정
    departure_distance=0.3,       # m, 배너 부제에 표시
    lkas=True,
    acc=True,
    fps=22.4,
    inference_ms=44.6,
)
```

`confidence` 는 모델의 신뢰도를 그대로 넣으면 됩니다. 마땅한 값이 없으면
검출된 차선 개수나 폴리라인 점 개수로 임시로 만들어 쓰다가 나중에 교체하세요.

## 속도

이 코드를 만든 환경에서 1024×600 기준 프레임당 12ms 정도 나옵니다.
라즈베리파이는 더 느리니 반드시 실제 장치에서 재보세요.

```bash
python3 hud_ui.py bench --theme
```

30fps 를 넘기려면 프레임당 33ms 아래여야 합니다. 넘으면 순서대로 시도하세요.

1. `theme.glow_scale` 을 3 에서 4~5 로 올린다 (가장 효과 큼, 글로우가 뭉개짐)
2. `theme.glow_gain` 을 1.6 에서 0.8 로 낮춘다
3. `theme.glow_gain` 을 0 으로 두어 글로우를 끈다 (블러 연산이 통째로 빠짐)
4. 그래도 부족하면 `display.width/height` 를 낮춘다

문서에 리본 정합 갱신을 60fps 이상으로 두라고 되어 있지만, 젠슨 추론이 22fps 라면
HUD 가 그보다 빨라도 표시가 갱신되지 않습니다. 30fps 를 목표로 잡고, 남는 여유는
글로우 품질에 쓰는 편이 낫습니다.

## 아직 안 된 것

문서 Open questions 중 다음 두 가지는 그대로 남아 있습니다.

1. **주간/야간 밝기 프로파일.** 조도 센서가 없어 설계하지 않았습니다. 지금은
   `theme.glow_gain` 과 각 요소 불투명도로 수동 조절만 됩니다. 야간에는 전체를
   30~50% 낮추는 편이 눈이 편합니다.
2. **우측 이탈 시안.** 좌측의 좌우 반전으로 처리한다는 가정을 그대로 따랐습니다.
   `departure_right` 를 보내면 반대쪽 경계선이 강조되고 배너 부제가 `우측` 으로
   바뀝니다.
