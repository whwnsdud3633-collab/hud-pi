# 운전자 시점 정렬 사용법

`hud_align.py` 는 **카메라가 본 차선과 운전자가 눈으로 본 차선을 같은 자리에 겹치게**
만드는 보정 도구입니다.

| 도구 | 하는 일 |
|---|---|
| `hud_system.py calibrate` | 화면 내용을 모니터의 어느 사각형 안에 넣을지 |
| `hud_align.py` | 카메라 좌표를 운전자 시점에 맞는 자리로 옮기기 |

앞의 것만 해서는 차선이 실제 도로와 어긋납니다. 카메라는 대시보드 위에 있고
운전자 눈은 그보다 뒤쪽 위에 있어서 두 시점이 애초에 다르기 때문입니다.

## 모니터를 움직여서 맞추면 안 되는 이유

모니터를 밀거나 돌리면 상 전체가 통째로 이동할 뿐입니다. 실제로 필요한 보정은
**사다리꼴 왜곡**입니다. 모니터가 운전자 시선에 비스듬히 누워 있어서, 화면에
직사각형을 그려도 반사된 상은 사다리꼴로 찌그러집니다. 여기에 카메라 시점과
운전자 시점의 차이까지 겹칩니다. 이건 하드웨어를 아무리 조정해도 없앨 수 없고,
소프트웨어에서 미리 반대로 찌그러뜨려 그려야 상쇄됩니다.

그래서 순서가 중요합니다.

1. 모니터 위치와 각도를 **대충 맞춰서 단단히 고정합니다.** 상이 시야 안에 들어오면 됩니다.
2. 그 다음 이 도구로 정밀 정렬합니다.

**2번을 마친 뒤 모니터를 움직이면 보정이 무효가 됩니다.** 흔들리지 않게 고정하세요.

## 카메라 장착 확인

카메라를 룸미러 뒤나 옆에 달면 운전자 눈과 높이·앞뒤 위치가 비슷해져서, 두 시점 차이가
작아지고 정렬이 더 안정적입니다. 대신 장착 전에 확인할 것이 있습니다.

- **와이퍼 범위 안인지.** 와이퍼를 켠 상태로 카메라 화면을 보고 렌즈 앞 유리가 실제로
  닦이는지 확인하세요. 빗길에서 여기가 안 닦이면 아무것도 안 됩니다.
- **대시보드 반사가 없는지.** 렌즈 주변에 검은 후드를 만들거나 대시보드에 검은 천을 깝니다.
- **접착식으로 고정했는지.** 흡착식은 온도 변화로 미끄러집니다. 1mm 만 움직여도 보정을
  다시 해야 합니다.
- **밤에 HUD 빛이 카메라에 잡히지 않는지.** 낮에는 없다가 밤에 나타납니다.

**보닛 가림도 확인하세요.** 카메라를 높이 달면 보통 앞 4~6m 부터 노면이 보이기 시작합니다.
`place` 로 십자를 찍을 때 여섯 자리가 전부 카메라 영상에도 보이는 노면이어야 합니다.
가까운 점이 보닛에 가려진 구간에 떨어지면 `W` 키로 위쪽(먼 쪽)으로 밀어서 옮기세요.

## 왜 행렬 하나로 되는가

차선은 노면 위에 있고 노면은 평면입니다. 그래서

```
카메라 영상 → 노면 → 운전자 시점 → HUD 패널
```

이 연결이 전부 평면 대 평면 대응이고, 호모그래피끼리 곱해도 호모그래피이므로
**최종 결과는 3×3 행렬 하나**입니다. 카메라 장착 위치, 눈 높이, 반사 각도,
좌우 반전이 전부 이 행렬 안에 흡수됩니다. 각각을 따로 재거나 모델링할 필요가 없습니다.

대신 이 행렬은 **실측으로만** 구할 수 있습니다. 노면 위의 같은 지점을 카메라 영상에서
한 번, HUD 화면에서 한 번 찍어 대응쌍 6개를 모으는 방식입니다.

## 두 가지 순서 중 고르기

같은 대응쌍을 모으는 순서가 두 가지입니다. **A 를 권합니다.**

| | A. HUD 먼저 | B. 꼬깔 먼저 |
|---|---|---|
| 순서 | HUD 가 점을 찍음 → 그 자리에 꼬깔 → 사진 촬영 | 꼬깔 배치 → 사진 촬영 → HUD 점을 꼬깔에 맞춤 |
| 거리 측정 | 필요 없음 | 꼬깔이 HUD 범위 안에 드는지 확인 필요 |
| 운전석 작업 | 지시만 | 십자 미세 조정 |
| 명령 | `place` → `pick` | `pick` → `aim` |

A 가 나은 이유는 **HUD 가 자기가 덮는 자리를 직접 알려주기 때문**입니다. 꼬깔을 먼저
놓으면 그게 HUD 범위 밖일 수 있는데, A 는 그럴 일이 없습니다. 자로 잴 필요도 없습니다.

참고로 시뮬레이션에서 계산해본 낙하 지점은 앞 4.6m / 7.4m / 17.4m, 좌우 ±0.7~1.3m
정도였습니다. 장비에 따라 달라지니 이 숫자를 믿지 말고 A 방식으로 직접 확인하세요.

# A 방식 (권장)

## 1단계 — HUD 가 자리를 찍어준다

평탄한 곳에 차를 세우고, 모니터를 고정한 뒤 실행합니다.

```bash
python3 hud_align.py place
```

운전석에 앉으면 흰 십자가 하나 보입니다. **유리 너머로 그 십자가 노면의 어느 지점에
겹쳐 보이는지** 확인하고, 조수가 그 자리에 꼬깔을 놓습니다. 놓았으면 엔터.
여섯 번 반복하면 끝입니다.

| 키 | 동작 |
|---|---|
| `W` `A` `X` `D` | 십자 이동 (방향키도 동작) |
| `F` | 이동 폭 1픽셀 ↔ 4픽셀 전환 |
| `Enter` | 이 자리 확정하고 다음으로 |
| `U` | 이전으로 되돌리기 |
| `Q` | 취소 |

십자를 움직일 일은 보통 없지만, 어떤 점이 벽이나 연석 위에 떨어지면 노면 위로
옮기세요. 나머지 점들과 너무 가까워지지만 않으면 됩니다.

## 2단계 — 꼬깔을 촬영해서 영상에서 찍는다

**꼬깔과 차를 그대로 둔 채로** 젯슨에서 그 장면을 저장합니다.

```python
cv2.imwrite("road.png", frame)
```

이 이미지를 노트북이나 파이로 옮긴 뒤:

```bash
python3 hud_align.py pick --frame road.png
```

꼬깔을 **1단계와 같은 순서로** 클릭합니다. 여섯 개를 다 찍고 `S` 를 누르면 그 자리에서
행렬을 계산하고 오차를 출력합니다.

| 키 | 동작 |
|---|---|
| 좌클릭 | 꼬깔 찍기 |
| `U` | 마지막 점 취소 |
| `S` | 계산하고 저장 |
| `Q` | 취소 |

# B 방식

꼬깔을 이미 놓아버렸거나 특정 지점에 꼭 맞추고 싶을 때 씁니다.

```bash
python3 hud_align.py pick --frame road.png   # 영상에서 꼬깔 클릭
python3 hud_align.py aim                     # 운전석에서 십자를 꼬깔에 겹치기
```

`aim` 은 십자를 하나씩 띄우니, 유리 너머 실제 꼬깔 위에 정확히 겹치도록 옮긴 뒤
엔터를 누릅니다. 키는 `place` 와 같고 `S` 로 계산·저장합니다.

이 방식은 꼬깔이 HUD 범위 밖에 있으면 십자를 아무리 옮겨도 닿지 않습니다. 그럴 땐
꼬깔을 옮기고 사진부터 다시 찍어야 합니다.

---

## 공통 주의

**꼬깔 배치 조건**

- 평면 위에만 놓습니다. 연석이나 턱 위는 안 됩니다. 평면 가정이 깨집니다.
- 넓게 퍼뜨립니다. 한 덩어리로 모이면 행렬이 불안정해집니다.
- 네 개가 한 직선 위에 오면 안 됩니다.

A 방식의 기본 여섯 자리는 이 조건을 만족하도록 배치해뒀습니다.

**머리를 고정해야 합니다.** 여섯 개를 다 끝낼 때까지 헤드레스트에 뒤통수를 붙인 자세를
유지하세요. 중간에 자세가 바뀌면 값들이 서로 안 맞습니다. 혼자서는 어려우니 한 명이
운전석에 앉고 다른 한 명이 꼬깔을 놓거나 키를 누르는 편이 낫습니다.

**오차 읽는 법**

```
reprojection error per marker (panel px):
  marker 1: 2.4
  ...
  mean: 3.0
```

평균 5픽셀 이하면 양호합니다. 15픽셀을 넘으면 어딘가 잘못된 것입니다. 꼬깔이 한쪽에
몰렸거나, 중간에 머리가 움직였거나, 두 단계의 순서가 어긋났을 가능성이 큽니다.

## 3단계 — 눈으로 확인

```bash
python3 hud_align.py verify
```

계산된 행렬로 꼬깔 자리에 십자를 다시 띄웁니다. 운전석에서 봤을 때 십자가 실제 꼬깔
위에 앉아 있으면 성공입니다. 전체가 조금씩 밀려 있으면 `W` `A` `X` `D` 로 통째로
밀어서 맞춘 뒤 `S` 로 저장합니다. 이 값은 `alignment.pan_x`, `pan_y` 에 들어갑니다.

운전자가 바뀌어 눈높이가 달라졌을 때도 이 미세 조정만으로 어느 정도 맞출 수 있습니다.
차이가 크면 1단계부터 다시 하세요.

# 시뮬레이터 시연

게임 화면 자체가 평면이고 차선이 그 평면 위에 그려지므로, 실차와 같은 논리가 그대로
적용됩니다. 오히려 실차보다 유리한 점이 있습니다. 실차에서는 노면 위 물체만 정렬됐지만
시뮬레이터에서는 화면에 보이는 모든 것이 같은 평면 위라 전부 정렬됩니다.

입력을 어떻게 받느냐에 따라 절차가 갈립니다.

## 화면 캡처 방식 (권장)

게임 프레임을 그대로 추론에 넣는 경우입니다. 표식 좌표를 이미 알고 있으므로
촬영과 클릭 단계가 통째로 사라집니다.

```bash
python3 hud_align.py preset --write-image 보정판.png
```

`보정판.png` 를 **게임 모니터에 전체화면으로** 띄웁니다. 십자 여섯 개가 나옵니다.
그 다음 운전석에 앉아서:

```bash
python3 hud_align.py aim
```

HUD 십자를 모니터의 십자에 하나씩 겹치고 엔터. 여섯 번이면 끝입니다.

## 물리 카메라 방식

카메라로 게임 화면을 촬영하는 경우입니다. 실차와 절차가 완전히 같습니다.

```bash
python3 hud_align.py pick --frame capture.png
python3 hud_align.py aim
```

`capture.png` 는 보정판을 띄운 게임 화면을 카메라로 잡은 프레임입니다.
`preset` 은 쓰면 안 됩니다. 카메라가 화면을 비스듬히 잡으면 십자가 예상 좌표에
있지 않기 때문입니다.

## 시뮬레이터에서 주의할 것

- **게임 카메라 시점을 고정하세요.** 보닛뷰, 실내뷰, FOV 설정을 바꾸면 보정이 무효입니다.
  시연 전에 설정을 확정하고 잠가두세요.
- **모니터와 HUD를 둘 다 고정하세요.** 하나라도 움직이면 다시 해야 합니다.
- **거리가 가까워 시차가 큽니다.** 실차에서는 도로가 멀어 머리를 조금 움직여도
  덜 어긋나지만, 화면이 1~2m 앞에 있으면 같은 머리 움직임에 더 크게 어긋납니다.
  아래 눈 위치 고정이 실차보다 더 중요합니다.

# 사람이 바뀔 때

시연에서 여러 명이 번갈아 앉는다면 매번 전체 보정을 반복할 수 없습니다.
방법이 세 가지 있고, 위쪽이 더 확실합니다.

## 1. 눈 위치를 고정한다 (가장 확실)

보정을 다시 하는 대신, 사람을 같은 자리에 앉히는 방법입니다. 실제 양산 HUD 도
아이박스를 정해놓고 이 방식을 씁니다.

준비물은 스티커 한 장입니다.

1. 보정을 마친 사람이 앉은 상태에서 `python3 hud_align.py eyebox` 를 실행합니다.
   화면 중앙에 흰 링이 뜹니다.
2. 그 사람 시점에서 링의 중심이 겹쳐 보이는 자리에 **앞유리에 작은 스티커**를 붙입니다.
3. 다음 사람은 앉아서 좌석 높이와 앞뒤를 조절해 **링과 스티커가 겹치게** 맞춥니다.

스티커는 유리 위에 있고 HUD 상은 유리 너머에 맺히므로, 깊이가 달라 시차가 생깁니다.
그래서 눈 위치가 어긋나면 둘이 어긋나 보입니다. 이걸 조준기로 쓰는 것입니다.
추가 장비 없이 10초면 됩니다.

## 2. 두 명분을 저장해 두고 사이를 섞는다

키 차이가 커서 좌석 조절로 안 될 때 씁니다. 키가 큰 사람과 작은 사람으로 각각
보정한 뒤 이름을 붙여 저장합니다.

```bash
# 작은 사람으로 보정을 마친 뒤
python3 hud_align.py profile --name short
# 큰 사람으로 다시 보정한 뒤
python3 hud_align.py profile --name tall
```

이후에는 `verify` 에서 `-` `=` 키로 두 프로필 사이를 섞으면서 맞추면 됩니다.
맞으면 `S` 로 저장합니다.

합성 데이터로 확인해보면, 두 눈높이 사이의 중간 지점에서 오차가 0.4픽셀 수준입니다.
전체 보정을 다시 하는 것과 사실상 차이가 없습니다.

## 3. 통째로 밀기

작은 차이는 `verify` 에서 `W` `A` `X` `D` 로 전체를 밀어서 흡수합니다.
가장 빠르지만 평행 이동뿐이라, 눈높이가 10cm 이상 차이나면 한쪽이 맞으면
다른 쪽이 어긋나기 시작합니다. 그때는 2번으로 넘어가세요.

## 4. 실데이터를 보며 키보드로 맞추기 (trim)

```bash
python3 hud_align.py trim          # 젯슨 패킷을 받으며
python3 hud_align.py trim --mock   # 젯슨 없이 가짜 차선으로
```

`receive` 와 같은 수신 경로로 젯슨 차선을 그려 놓고, 운전석에서 실제 차선을 보며
그 위에 얹힌 오버레이를 키로 맞춥니다. 행렬을 다시 풀지 않고 위에 작은 보정 하나를
더 곱하는 방식이라 1~3단계의 결과를 건드리지 않습니다. **`hud_ui.py receive` 가
떠 있으면 먼저 끄세요.** 같은 포트를 잡으면 패킷을 한쪽만 받습니다.

| 키 | 동작 (전부 운전자가 보는 방향 기준) |
|---|---|
| ← → ↑ ↓ | 평행이동 |
| `w` / `s` | 위쪽 폭 넓게 / 좁게. 화면 맨 아랫줄은 고정 |
| `a` / `d` | 반시계 / 시계 기울기. `d` 는 오른쪽이 내려가고 왼쪽이 올라감 |
| `f` 또는 `Tab` | 작은 폭 / 큰 폭 전환 |
| `0` | 보정 전으로 리셋 |
| `Enter` | 저장 |
| `q` 또는 `Esc` | 종료. 저장 안 했으면 한 번 더 묻는다 (Enter 저장 후 종료, `q` 버리고 종료, 다른 키 취소) |

`flip_horizontal` 이 켜져 있어도 키 방향은 운전자 기준으로 맞춰져 있습니다.
오른쪽 키를 누르면 패널에서는 왼쪽으로 가고, 반사된 상에서는 오른쪽으로 갑니다.
화면 위 안내 글자도 같은 이유로 패널에는 거울 글씨로 그려집니다.

Shift 조합은 쓰지 않습니다. 이 파이의 OpenCV(Qt 백엔드)는 키 코드에 Shift 상태를
싣지 않아서 Shift+방향키가 그냥 방향키로 들어옵니다.

순서는 **평행이동으로 가까운 차선을 먼저 맞추고 → `w` `s` 로 먼 쪽 벌어짐 → `a` `d` 로
좌우 기울기** 가 편합니다. 사다리꼴 축이 화면 맨 아래라서 앞서 맞춘 가까운 쪽이 덜
흔들립니다.

한 번 누를 때 움직이는 양은 `alignment.trim_step` 에서 바꿉니다.

## 시연 진행 순서 제안

1. 대표 한 명으로 전체 보정 후 `profile --name main` 저장
2. 체격이 많이 다른 한 명으로 한 번 더 보정 후 `profile --name tall` 저장
3. 스티커를 붙여 아이박스 조준점을 만든다
4. 시연 때는 앉히고 → 스티커에 링 맞추게 하고 → 필요하면 `-` `=` 로 미세 조정

## 저장되는 값

```json
"alignment": {
  "mode": "correspondence",
  "camera_horizon_y": 0.0,
  "horizon_margin": 0.18,
  "pan_x": 0,
  "pan_y": 0,
  "blend": 0.0,
  "trim": { "dx_px": 0.0, "dy_px": 0.0, "keystone": 0.0, "roll_deg": 0.0 },
  "trim_step": {
    "fine":   { "move_px": 1.0, "keystone": 0.002, "roll_deg": 0.05 },
    "coarse": { "move_px": 8.0, "keystone": 0.01,  "roll_deg": 0.5 }
  },
  "profiles": [ { "name": "short", "panel": [[214, 508], ...] } ],
  "pairs": [
    { "camera": [0.31, 0.62], "panel": [214, 508] },
    ...
  ]
}
```

`mode` 가 `correspondence` 면 실측 정렬을 씁니다. `quad` 면 예전 방식으로 되돌아갑니다.
정렬 전에도 화면 구성 작업은 할 수 있게 `quad` 가 기본값입니다.

`trim` 은 `hud_align.py trim` 이 저장하는 값입니다. 모드와 상관없이 마지막에 곱해지고,
전부 0 이면 아무 일도 하지 않습니다. `dx_px`, `dy_px` 는 패널 픽셀, `keystone` 0.01 은
화면 맨 윗줄 폭 약 2%, `roll_deg` 는 도 단위입니다.

`camera_horizon_y` 는 0이면 자동입니다. 소실선 근처에서 좌표가 발산하는 구간을 보정
데이터로부터 알아서 잡습니다. 카메라 각도를 바꿔도 손댈 필요가 없습니다.
지평선 부근에서 선이 튀면 `horizon_margin` 을 0.18 에서 0.3 정도로 올리세요.

## 알아둘 한계

**노면 위에 있는 것만 맞습니다.** 앞차나 표지판처럼 노면에서 떨어진 물체는 이 행렬로
정렬되지 않습니다. 차선만 그리는 지금 구성에서는 문제가 없습니다.

**눈 위치 하나에만 맞습니다.** HUD 상은 유리 앞 어딘가에 맺히므로, 머리를 움직이면
시차 때문에 어긋납니다. 좌석을 앞뒤로 옮기거나 운전자가 바뀌면 3단계를 다시 하세요.
대회 시연이라면 누가 앉을지 미리 정하고 그 사람 기준으로 보정해두는 게 안전합니다.

**HUD는 도로의 일부 구간만 덮습니다.** 7인치 패널이 만드는 상은 시야의 좁은 띠라서,
아주 가까운 노면과 지평선 근처는 화면 밖으로 나갑니다. `hud_ui.py` 가 화면을 벗어나는
부분을 잘라서 그리니 오류는 아니고, 원래 그렇게 보이는 게 정상입니다.

**보정은 차 위치가 아니라 카메라·눈·유리의 관계를 잡는 것입니다.** 보정을 마친 뒤
차를 움직여도 정렬은 유지됩니다. 카메라를 다시 달거나 좌석을 조정했을 때,
그리고 모니터를 움직였을 때만 다시 하세요.

## 보정 시점

모든 단계를 **정차 상태에서** 끝내야 합니다. 십자와 꼬깔을 겹치는 작업이라
차가 움직이면 애초에 성립하지 않습니다.
